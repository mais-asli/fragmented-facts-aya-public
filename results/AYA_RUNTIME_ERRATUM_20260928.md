# Runtime erratum for the new Aya source cohorts

The first source-backed U/D Slurm jobs (945444–945447) **failed before model loading and before producing any Aya answer**. Their TAU logs show `TypeError: 'PosixPath' object is not subscriptable` at the `load_runner` call: the run code passed the path of the model settings file instead of the parsed settings object. The logs and Slurm states are saved in `results/tau_source_verified_diagnostic_20260928.txt`. The first source-disjoint E5 jobs (945480–945481) also ended without completion; their run code contained the same loader-call defect. The E5 logs were not separately retrieved, so the exact terminal error for those two jobs is unconfirmed.

The original code and protocols are preserved in `configs/failed_launch_20260928/`. In both runners, only the loader call changed from `load_runner(SNAPSHOT, CONFIG)` to `load_runner(SNAPSHOT, read_json(CONFIG))`. The source U/D protocol's pinned runner hash was updated, and the E5 protocol's link to that source protocol was updated. The data, subject selection, name forms, prompts, distractors, model revision, precision, prespecified outcomes, analysis plans, E5 donors, layer window, and patch site did not change. The new protocol files contain a timestamped runtime-erratum field. The recovery workflows use new Slurm state files, keeping the failed job record intact.

The corrected source U/D protocol SHA-256 is `1070611805d78e63b3f29705f43507e0d5f0d3aec0bf34fcf5bc204f10acaf0c`; the corrected E5 protocol SHA-256 is `03c3e8b51e913b54181967d75402e72bdcde706d3e91f31493fdd7c5793d5155`. These corrections were made before any returned source U/D or new E5 model outputs were available. The completed E6 experiment has a separate frozen protocol and was unaffected.

Local checks after the fix: both revised Python workflows compile; every source U/D pinned file hash and the E5 source-protocol link verify; source Arabic and E5 Hebrew tokenizer dry runs pass. A mocked loader-interface check reached the real non-dry-run call in both scripts and confirmed that it receives a settings dictionary with `precision=nf4`. This confirms the repaired call and frozen input identities, but only a successful TAU run can verify full GPU execution.

The TAU receiver initially refused the corrected protocol because it preserves existing paths by default. The retry therefore uploads the original files into `configs/failed_launch_20260928/` on TAU and permits replacement of only six specified working paths when their current SHA-256 hashes exactly match the recorded first-launch hashes. Its new Slurm state files have `retry1` in their names; the original failed job records remain intact. A mismatch aborts before job submission.
